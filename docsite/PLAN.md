# websocketd docs: information architecture

The site map, and the objective of every page in it. Built on
[Diátaxis](https://diataxis.fr/); the writing rules that go with it are
in [STYLE.md](STYLE.md).

**Facts come from `docs-archive/MANUAL_INVENTORY.md` (archived research) and
from the code itself — and the code wins wherever the two disagree, which by
now they do.** The previous version of this site is a
usable source of *verified facts* (flag defaults, the teardown ladder
timings, the `--cgidir` environment differences, per-language buffering
fixes). It is not a source of prose. Every page is written fresh.

## Page objectives

Each line is the single outcome the page must deliver. If a draft
doesn't deliver it, the draft is wrong.

### Landing
- **`/`** — A reader who has never heard of websocketd understands what
  it does in under thirty seconds, sees one real command, and knows
  where to start.

### start/ (Tutorial)
- **`start/`** — The reader knows what they're about to do and what
  they need before starting.
- **`start/install`** — The reader has a working `websocketd` binary on
  their `PATH`, by whichever route suits their machine.
- **`start/tutorial`** — The reader has wrapped a script, talked to it
  from a browser, and served their own page — with every trap from
  issue #438 defused *at the moment it would bite*.

### how-to/languages/ (How-to)
Each page: the reader's script in that language streams output correctly.
- **`python`** — `-u`, or `flush()`; and why `PYTHONUNBUFFERED` needs `--passenv`.
- **`ruby`** — `STDOUT.sync = true`.
- **`nodejs`** — stdin read correctly with `readline`; output needs no flush.
- **`php`** — `flush()`/`ob_flush()`, and the `<?` short-tag trap.
- **`c`** — `setbuf(stdout, NULL)` or `fflush`.
- **`windows-scripts`** — running `.bat`/`.cmd`/`.ps1`; no shebangs; PATH aliasing.

### how-to/deploy/ (How-to)
Each page: a working configuration, tested shape, caveats after.
- **`nginx`** — WebSocket upgrade proxied correctly (the two headers nginx drops).
- **`apache`** — `mod_proxy_wstunnel`.
- **`haproxy`** — HTTP-mode backend carrying the upgrade.
- **`systemd`** — starts at boot, restarts on failure.
- **`docker`** — a working container; the no-pty limitation stated first.
- **`kubernetes`** — Deployment + Service + WebSocket-aware Ingress.
- **`tls`** — `wss://` with `--ssl`, plus mutual TLS with `--sslca`
  (and the trap that `--sslca` alone silently does nothing).
- **`share-a-port`** — one port, two servers, via a reverse proxy.
- **`public-internet`** — checklist before exposing it beyond localhost.

### how-to/patterns/ (How-to)
- **`share-state`** — cross-connection state via message bus, FIFO, or a
  long-lived backend; how to choose.
- **`add-auth`** — authentication in front of websocketd (proxy), or
  inside the script (token).
- **`run-once`** — make a program run exactly once, or stay running.
- **`pass-arguments`** — query string vs. `--passenv`, and the confusion
  between them.
- **`debug-a-script`** — drive an endpoint with `--devconsole` before
  writing any client code.

### reference/ (Reference)
- **`cli-flags`** — every flag, default, and factual gotcha. *Generated:
  edit `tools/gendocs`, not this file.*
- **`environment-variables`** — every variable set for a spawned process,
  what populates it, and which are client-controlled.
- **`exit-codes`** — every exit code and its trigger.
- **`dev-console`** — what `--devconsole` serves, its mutual exclusions,
  its DOM/CSP contract.
- **`platform-support`** — supported platforms; the factual list of what
  differs on Windows.
- **`examples`** — what ships in `examples/`, per language, and how to
  run each.

### understanding/ (Explanation)
- **`process-model`** — why one process per connection, what that rules
  out, and what it buys.
- **`message-framing`** — why newlines are the frame boundary, and
  precisely what `--binary` does and doesn't change.
- **`output-buffering`** — why runtimes withhold output when stdout is a
  pipe. No fixes here; they live in `how-to/languages/`.
- **`process-lifecycle`** — when a process starts, the teardown ladder
  with real timings, and what a long-running program must handle.
- **`cgi-environment`** — how a request becomes an environment, and
  where the trust boundaries are. The variable table lives in reference.
- **`security-model`** — the origin policy and its permissive default,
  TLS, why there's no built-in authentication, the standing deliberate
  defaults, and the one open gap (issue #476).
- **`design-decisions`** — why not broadcast, why no pty, why no auth,
  why manual version numbers; the process pool and multi-socket attempts
  that were built and reverted.

### faq/ (Signpost)
- **`faq/`** — the ten questions that dominate this project's issue
  history, each answered in one or two sentences with a link to the page
  that owns it. No fact originates here.

### changelog
- **`changelog`** — what changed, rendered from `CHANGES`.

## What this replaces

The previous structure mixed modes: `guide/` held explanation *and*
how-to (buffering fixes next to conceptual framing), `platform-notes/`
held reference facts as prose, and `security/` mixed a posture
explanation with a reference list of defaults. Splitting on Diátaxis
lines is the whole point of the rewrite — nothing here is a rename for
its own sake.
